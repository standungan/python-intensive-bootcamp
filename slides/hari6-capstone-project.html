Perencanaan

PerencanaanMulai dari pertanyaan analisis

Pertanyaan yang baik

  • spesifik & bisa dijawab dengan data
  • "Apakah jam belajar berpengaruh pada nilai?"
  • "Prodi mana dengan rata-rata IPK tertinggi?"

Pertanyaan yang lemah

  • terlalu umum: "Analisis data ini"
  • tidak bisa diukur: "Mana yang bagus?"
Tulis 3–5 pertanyaan sebelum menulis kode — itu menentukan grafik dan insight.
Peserta menulis pertanyaan di workbook (L1).

PerencanaanStruktur folder proyek

Pisahkan data mentah dari data hasil olahan — data mentah tidak pernah diubah.
Path relatif tergantung folder tempat program dijalankan → pakai Path(__file__).
Struktur folder yang direkomendasikan modul. Peserta membuatnya di workbook (L2).

Pengerjaan Capstone

Clean → Analyze → Visualize → Insight

180 menit coding mandiri. Keliling, bantu yang buntu, jangan memberi solusi penuh.

PengerjaanSaran alokasi waktu coding (180 mnt)

Jangan terlalu lama di cleaning. Cukup baik > sempurna tapi kehabisan waktu. Kerjakan visualisasi terpenting dulu. Simpan sesering mungkin.
Tips manajemen waktu dari modul.

PengerjaanPipeline yang rapi: satu function, satu tugas

def muat_data(path): ...
def bersihkan(df): ...
def analisis(df): ...
def buat_grafik(df, out_dir): ...
def main():
    df = bersihkan(muat_data(PATH))
    hasil = analisis(df)
    buat_grafik(df, OUT)

if __name__ == "__main__":
    main()
Function kecil lebih mudah diuji & diperbaiki.
Sertakan docstring singkat + error handling pada baca file / panggil API.
Kode harus bisa dijalankan dari atas ke bawah tanpa error.
Standar kualitas kode: nama bermakna, function/class, docstring, PEP 8, error handling.
